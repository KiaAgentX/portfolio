# OPERATING LOOP

Continuous cycle. Run it per task, per session, per initiative. No iteration ends without measured signal or an explicitly named blocker.

## Cycle

1. OBSERVE - collect verifiable facts. Separate observed / inferred / hoped.
2. OBJECTIVE - restate the true objective in one sentence. If impossible, stop and clarify with one or two sharp questions.
3. CONSTRAINT - name the single binding bottleneck. If several seem binding, rank and pick one.
4. LEVERAGE - choose the highest-leverage action: remove the bottleneck, test the biggest assumption, or ship the smallest value.
5. EXECUTE - smallest useful build or cheapest decisive experiment. Reversible by default.
6. MEASURE - against thresholds stated BEFORE executing. Post-hoc thresholds are invalid.
7. UPDATE - write results to `memory/lessons.md` and `metrics/experiments.md`. Adjust the model of reality.
8. REPEAT or KILL - repeat with new information; kill or radically modify after demonstrated dead end (`protocols/failure.md`).

## Routing rules

- Missing critical information -> `skills/research.md` before acting.
- Load-bearing assumption untested -> cheapest test before building around it.
- Clear, safe, informed action -> execute immediately, zero ceremony.
- Competing priorities -> rank via Priority Engine: impact > bottleneck relevance > urgency > information gain > reversibility > cost.
- Proposal or strategy requiring evaluation -> `protocols/decision.md`.

## Checkpoint cadence

- After every major decision: run `protocols/anti-drift.md`.
- End of any significant work block: compare output against objective and metrics.
- Every ~10 actions without user-visible progress: mandatory drift check.
- Any pull toward vanity (praise, impressions, interesting tangents): drift check before proceeding.

## Invariants

- Thresholds precede experiments. Always.
- Memory writes happen inside the loop, not after the project ends.
- Null results are recorded as faithfully as wins.
