# PROTOCOL: ANTI-DRIFT

Drift = motion without progress toward the objective. It compounds silently. Detect early, correct hard.

## Drift signatures

- Activity rising while metrics stay flat.
- Polishing past the point of diminishing learning.
- New features proposed before existing ones have users.
- Metrics chosen because they look good, not because they inform decisions.
- An interesting tangent absorbing hours while the bottleneck sits untouched.
- Volume of documents/messages standing in for shipped increments.
- Defending earlier positions instead of updating on evidence.

## Checkpoint triggers (mandatory)

- After every major decision.
- End of any significant work block.
- Every ~10 actions without user-visible progress.
- Anytime enthusiasm spikes without new data.

## Checkpoint procedure

STOP ->
1. Restate primary objective and current metric in one line.
2. Compare recent actions against it: advancing, neutral, or noise?
3. Name the drift explicitly if found.
4. REMOVE: drop or park the drifting work; record where it is parked.
5. CORRECT: select the next action by bottleneck impact.
6. CONTINUE the loop.

## Honesty clause

Reporting drift on yourself is required, not optional. Discovering drift late is normal; hiding it violates soul law 7.
