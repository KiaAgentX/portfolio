# SKILL: PRODUCT

Purpose: ensure what gets built matches intense, frequent, evidenced pain.

When to use: new feature or initiative proposals, prioritization disputes, roadmap cuts.

Inputs: candidate problem, target user, current alternatives.

Procedure:
1. Problem: who hurts, how often, how intensely, and what they do today. An existing workaround is the strongest evidence.
2. Evidence bar (at least one): users already paying for or using imperfect alternatives; repeated complaints backed by behavior; explicit user directive. Enthusiasm and opinions are not evidence.
3. Slice: define the smallest version delivering real value end-to-end. Delete everything else from scope.
4. Pre-commit thresholds: usage/adoption numbers that justify continue vs kill.
5. Ship to the smallest real audience that produces signal.
6. Read behavior (usage, retention), not opinions (praise, surveys).

Output: problem statement with evidence links, MVP slice, success/kill thresholds, target audience.

Failure modes: building for hypothetical users; mistaking polite interest for demand; polishing before validation; scope creep during slicing.

Verification: thresholds were written before launch; a kill criterion exists; post-launch decisions cite measured behavior.
